# EPL 26-27 TOP5 내기

프리미어리그 26-27 시즌 1~5위 맞추기 내기의 점수판.
열 때마다 ESPN에서 현재 순위를 직접 가져와 다시 계산하고, 남은 경기를 시뮬레이션해 시즌 마감 순위까지 예측한다.
외부 라이브러리 없이 HTML 한 파일로 돌아간다.

---

## 예측값 고치기

`index.html` 을 텍스트 편집기로 열고 맨 위 `PREDICTIONS` 만 고치면 된다. 다른 곳은 건드릴 필요 없다.

```js
const PREDICTIONS = [
  { name: "유성", picks: ["아스날", "맨시티", "리버풀", "첼시", "맨유"] },
  { name: "민수", picks: ["맨시티", "아스날", "첼시", "리버풀", "뉴캐슬"] }
];
```

- `picks` 는 **순서대로 1위, 2위, 3위, 4위, 5위** 예측이다.
- 팀 이름은 한글 약칭·정식명·영문 아무거나 된다. `맨유` `맨체스터 유나이티드` `Man United` 전부 인식한다.
- 인원 수에 제한은 없다. 줄을 추가하면 된다.
- 못 알아듣는 이름이 있으면 리더보드 아래에 빨간 글씨로 어떤 이름인지 알려준다.

## 채점 규칙

팀 하나당:

```
예측한 팀이 실제 5위 안에 들었으면   3점 + max(0, 3 - 순위차)
5위 밖이면                          0점
```

| 순위차 | 0칸 | 1칸 | 2칸 | 3칸 이상 | 5위 밖 |
|--------|-----|-----|-----|----------|--------|
| 점수   | 6   | 5   | 4   | 3        | 0      |

5팀 합계 **30점 만점**. 동점이면 정확히 맞춘 팀 수 → 5위권 적중 팀 수 순으로 가른다.

## 마감 순위는 어떻게 예측하나

지금 승점을 38경기로 늘리는 방식이 아니다. 시즌 초에 그렇게 하면 노이즈를 그대로 확대할 뿐이다.

1. **팀마다 공격력·수비력 두 값**을 추정한다. 경기별 기대 득점 = 리그 평균 × 홈 이점 × 내 공격력 ÷ 상대 수비력.
2. 학습 데이터는 **직전 3시즌(앱에 내장) + 올 시즌 치른 경기**. 오래된 경기는 **180일마다 비중이 절반**이 된다.
   그래서 시즌 초엔 전년 성적이 전력을 거의 정하고, 경기가 쌓일수록 올 시즌 결과가 커진다. 전년과 올 시즌을 섞는 비율을 따로 정할 필요가 없다.
3. 득점만 보지 않고 **유효슈팅을 득점으로 환산해 40% 섞는다.** 운 좋게 들어간 골에 휘둘리지 않게.
4. **승격팀**은 올라온 첫 시즌 전력을 모르므로 직전 시즌 **강등팀들의 평균 전력**에서 출발한다.
5. **배당이 나온 경기**(보통 2~4주 앞까지)는 승/무/패를 배당 확률(북메이커 마진 제거)로 뽑고, 나머지는 모델로 뽑는다.
6. 매 시뮬레이션마다 팀의 '진짜 실력'을 한 번씩 다시 흔든다 — 부상·이적·폼 같은 불확실성. 시즌이 진행될수록 흔들림은 줄어든다.
7. **남은 경기 전부를 4,000회** 돌려 스코어를 뽑고, 매번 최종 순위표(승점 → 득실 → 득점)를 만들어 채점한다. (폰에서도 몇 초 안에 끝나면서 우승 확률 오차가 ±1.5%p 수준으로 들어오는 지점이다)
8. 나오는 것: 팀별 5위 안 진입 확률, 참가자별 기대 점수와 **내기에서 1위 할 확률**.

### 왜 이 방식인가 — 백테스트

21-22 ~ 25-26 다섯 시즌을 4R·10R·19R·29R 시점에서 잘라, 그 시점까지의 데이터로만 예측하고 실제 결과와 대조했다.

| 방식 | 4R 시점 최종승점 오차 | 전 시점 평균 오차 | 경기 결과 로그손실 |
|---|---:|---:|---:|
| 이전 버전 (전년 승점 Elo + 올 시즌 보정) | 12.5점 | 8.57점 | 1.010 |
| 올 시즌 결과만 쓸 때 | 14.4점 | 9.12점 | 1.014 |
| **현재 버전** | **10.9점** | **7.77점** | **0.985** |

- 다섯 시즌 **모두** 이전 버전보다 경기 결과를 더 잘 맞혔다.
- **상대전적**을 예측에 넣어 보면 다섯 시즌 모두 오히려 더 틀렸다. 시즌당 맞대결 두 경기로는 전력 차 이상의 정보가 없다. 그래서 일정 탭에 참고로 **표시만** 한다.
- 배당 반영(5번)만은 과거 배당 자료가 없어 백테스트하지 못했다.

## 공유하기 — GitHub Pages

⚠️ **파일을 카톡으로 보내서 더블클릭으로 열면 순위를 못 가져온다.** 브라우저가 `file://` 에서 외부 요청을 막기 때문이다. 반드시 웹 주소(`https://`)로 열어야 한다.

1. GitHub에 새 저장소를 만든다 (개인 계정, 이름은 아무거나).
2. **이 폴더의 파일 5개를 전부** 올린다 — `index.html` `manifest.json` `icon-192.png` `icon-512.png` `icon-maskable-512.png`.
   (`verify.js` `make_icons.py` `README.md` 는 올려도 되고 안 올려도 된다)
3. 저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)** 저장.
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/` 이 열린다. 이 주소를 공유하면 된다.

예측값을 바꾸려면 `index.html` 을 수정해 커밋하면 같은 주소에 그대로 반영된다.

## 폰에서 앱처럼 쓰기

앱스토어에 올릴 필요 없다. 위 주소를 폰 브라우저로 연 다음 **홈 화면에 추가**하면 아이콘이 생기고, 주소창 없는 전체화면으로 뜬다. 설치한 앱과 구분이 안 된다.

- **아이폰** — Safari로 열고 (크롬 말고 **Safari 여야 한다**) 아래 공유 버튼 → `홈 화면에 추가`
- **안드로이드** — Chrome으로 열고 우측 상단 ⋮ → `홈 화면에 추가` 또는 `앱 설치`

들어가 있는 것: 전체화면 실행, 프리미어리그 사자 홈 화면 아이콘, 세로 고정, 노치·하단 제스처바 여백 처리.

아이콘은 ESPN이 제공하는 리그 로고에서 워드마크를 빼고 사자만 크롭해 만든다(`make_icons.py`). 프리미어리그 로고는 리그의 상표이므로 개인 내기 앱 식별용으로만 쓴다.

인터넷 없이 여는 오프라인 모드는 넣지 않았다. 어차피 매번 최신 순위를 받아와야 하는 앱이라 의미가 없다.

> 공개 저장소의 Pages는 **링크를 아는 누구나 접근할 수 있는 공개 인터넷**이다. 개인적인 내용이나 회사 관련 정보는 절대 넣지 말 것.

### 경기가 진행 중일 때

일정 탭 맨 위에 **지금 진행 중** 구역이 생기고 현재 스코어가 붉게 표시된다.
헤더에도 몇 경기가 돌고 있는지 나온다.

주의할 점이 하나 있다. 진행 중인 경기를 순위표가 이미 셈에 넣었다면,
시뮬레이션에서 그 경기를 다시 돌릴 경우 **같은 경기를 두 번 세게 된다**.
ESPN 순위표가 라이브로 반영하는지 여부는 리그·시점에 따라 다를 수 있어
추측하지 않고 데이터로 판별한다 — 리그 전체 '치른 경기 수'의 합은 언제나
경기 수의 두 배여야 하므로, 그 합이 진행 중 경기까지 포함하는지 보면 알 수 있다.
반영됐으면 시뮬레이션에서 빼고, 아니면 남은 경기로 돌린다.

### 언제 갱신되나

열 때마다 ESPN에서 현재 순위와 일정(배당 포함)을 새로 받아 계산한다. 예측값을 고치거나 따로 돌릴 필요가 없다.
경기 결과는 네 갈래로 반영된다 — 시뮬레이션의 출발 승점, 팀 공격·수비력 재추정, 남은 경기 수,
그리고 실력 불확실성의 폭. 마지막 항목 때문에 경기가 쌓일수록 예측이 점점 좁고 확신 있게 바뀐다.

| 시점 | 치른 경기 | 실력 흔들림 폭 (득점력 기준) |
|---|---|---|
| 시즌 초 | 4경기 | ±15% |
| 중반 | 19경기 | ±10% |
| 막판 | 30경기 | ±7% |

단, 앱을 켜 둔 채로는 다시 계산하지 않는다. 예측 탭의 **최신 결과로 다시 계산** 버튼을 누르면
받아둔 응답 캐시까지 비우고 순위·일정·예측을 전부 새로 받는다.

### 기대 점수와 우승 확률이 다를 때

예측 탭에서 **기대 점수는 낮은데 우승 확률은 더 높은** 사람이 나올 수 있다. 버그가 아니다.

- **기대 점수** = 전체 시뮬레이션의 평균. "보통 몇 점 나오나"
- **우승 확률** = 그중 실제로 1등한 비율. "몇 번 이기나"

확률 낮은 시나리오에서 크게 터지는 픽은 평균을 끌어올리지만 매번 이기지는 못한다. 반대로 흔한 시나리오에 맞춘 픽은 평균이 조금 낮아도 이기는 횟수가 많다. 내기는 평균이 아니라 그 판의 최고점으로 가리므로 **우승 확률 쪽이 실제 승부에 가깝다.**

리더보드의 `마감 예측` 점수는 또 다르다. 평균이 아니라 **모든 팀이 자기 평균 순위에 앉은 대표 시나리오 한 판**을 채점한 값이다. 현실에서 그런 판은 거의 안 나오므로 셋이 어긋나는 게 정상이다.

## 검증

```bash
node verify.js          # 실제 ESPN API를 호출해 148개 항목 검사
node verify.js --fast   # 시뮬레이션을 1000회로 줄여 빠르게
```

`verify.js` 는 `index.html` 안의 스크립트를 **그대로 꺼내서** 돌린다. 로직을 복사해 두지 않으므로 앱과 검증이 어긋날 수 없다.

검사 항목: 채점 규칙 32개 조합 대조표, 총점·만점 정합성, 동점 처리, 배당 파싱(미국식→소수·마진 제거·링크 미수집), 포아송 난수 평균·분산, 내장 과거 3시즌 무결성, ESPN 응답 수신, 순위표 자체 교차검증(승점 = 승×3+무 등), 전력 모델(내장 25-26 경기로 센 승점 = ESPN 최종 순위표, 승격·강등팀, 확률 범위), 시뮬레이션 확률 합, 일정 탭 배당·출처·맞대결, 배당 반영 스위치, 엔드포인트별 응답 구조 차이, 탭 진입 회귀, 홈 화면 앱 구성, 외부 의존성 검사.

## 데이터

ESPN 공개 API. API 키가 필요 없고 `Access-Control-Allow-Origin: *` 이라 브라우저에서 직접 부를 수 있다.

| 쓰임 | 엔드포인트 |
|------|-----------|
| 현재 순위 | `/apis/v2/sports/soccer/eng.1/standings` |
| 전체 일정 · 유효슈팅 · 배당 | `/apis/site/v2/.../scoreboard?dates=YYYYMMDD-YYYYMMDD` (배당 = `competitions[0].odds[0]`, DraftKings) |
| 선수단 | `/apis/site/v2/.../teams/{id}/roster` |
| 팀 로고 | `a.espncdn.com/combiner/i?img=/i/teamlogos/soccer/500/{id}.png&h=64&w=64` |
| (검증용) 전시즌 최종 | 현재 순위 주소 + `?season=2025` — 내장 데이터와 승점 대조 |

과거 3시즌(23-24 ~ 25-26) 1,140경기의 스코어·유효슈팅은 `index.html` 안의 `HIST` 에 압축해 넣었다(약 25KB).
끝난 시즌이라 바뀌지 않고, 폰에서 매번 시즌당 4MB 를 받지 않기 위해서다.
유효슈팅이 0:0 으로 찍힌 22경기(골이 난 경기인데도)는 기록 누락으로 보고 득점만 쓴다.

배당은 **다가올 2~4주 경기에만** 올라온다. 화면 표시와 예측에만 쓰고, 응답에 들어 있는 베팅 사이트 링크는 가져오지 않는다.

외부 라이브러리는 하나도 쓰지 않는다. 파일 하나가 전부다.
