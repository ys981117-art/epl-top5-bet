# EPL 26-27 TOP5 내기

프리미어리그 26-27 시즌 1~5위 맞추기 내기의 점수판.
열 때마다 ESPN에서 현재 순위를 직접 가져와 다시 계산하고, 남은 경기를 시뮬레이션해 시즌 마감 순위까지 예측한다.
외부 라이브러리 없이 HTML 한 파일로 돌아간다.

---

## 예측값 고치기

`index.html` 을 텍스트 편집기로 열고 맨 위 `PREDICTIONS` 만 고치면 된다. 다른 곳은 건드릴 필요 없다.

```js
const PREDICTIONS = [
  { name: "유성", picks: ["아스날", "맨시티", "리버풀", "첼시", "맨유"] },
  { name: "민수", picks: ["맨시티", "아스날", "첼시", "리버풀", "뉴캐슬"] }
];
```

- `picks` 는 **순서대로 1위, 2위, 3위, 4위, 5위** 예측이다.
- 팀 이름은 한글 약칭·정식명·영문 아무거나 된다. `맨유` `맨체스터 유나이티드` `Man United` 전부 인식한다.
- 인원 수에 제한은 없다. 줄을 추가하면 된다.
- 못 알아듣는 이름이 있으면 리더보드 아래에 빨간 글씨로 어떤 이름인지 알려준다.

---

## 채점 규칙

팀 하나당:

```
예측한 팀이 실제 5위 안에 들었으면   3점 + max(0, 3 - 순위차)
5위 밖이면                          0점
```

| 순위차 | 0칸 | 1칸 | 2칸 | 3칸 이상 | 5위 밖 |
|--------|-----|-----|-----|----------|--------|
| 점수   | 6   | 5   | 4   | 3        | 0      |

5팀 합계 **30점 만점**. 동점이면 정확히 맞춘 팀 수 → 5위권 적중 팀 수 순으로 가른다.

---

## 마감 순위는 어떻게 예측하나

지금 승점을 38경기로 늘리는 방식이 아니다. 시즌 초에 그렇게 하면 노이즈를 그대로 확대할 뿐이다.

1. **25-26 최종 승점**으로 팀별 초기 실력(Elo)을 잡는다. 승격팀은 하위권 기본값을 준다.
2. **올 시즌 치른 경기**로 그 Elo를 보정한다.
3. 매 시뮬레이션마다 팀의 '진짜 실력'을 한 번씩 다시 뽑는다 — 부상·이적·폼 같은 불확실성. 시즌이 진행될수록 이 폭은 줄어든다.
4. **남은 경기 전부를 4,000회** 돌려 승/무/패와 골득실을 뽑고, 매번 최종 순위표를 만들어 채점한다. (폰에서도 몇 초 안에 끝나면서 우승 확률 오차가 ±1.5%p 수준으로 들어오는 지점이다)
5. 나오는 것: 팀별 5위 안 진입 확률, 참가자별 기대 점수와 **내기에서 1위 할 확률**.

## 공유하기 — GitHub Pages

⚠️ **파일을 카톡으로 보내서 더블클릭으로 열면 순위를 못 가져온다.** 브라우저가 `file://` 에서 외부 요청을 막기 때문이다. 반드시 웹 주소(`https://`)로 열어야 한다.

1. GitHub에 새 저장소를 만든다 (개인 계정, 이름은 아무거나).
2. **이 폴더의 파일 5개를 전부** 올린다 — `index.html` `manifest.json` `icon-192.png` `icon-512.png` `icon-maskable-512.png`.
   (`verify.js` `make_icons.py` `README.md` 는 올려도 되고 안 올려도 된다)
3. 저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)** 저장.
4. 1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/` 이 열린다. 이 주소를 공유하면 된다.

예측값을 바꾸려면 `index.html` 을 수정해 커밋하면 같은 주소에 그대로 반영된다.

## 폰에서 앱처럼 쓰기

앱스토어에 올릴 필요 없다. 위 주소를 폰 브라우저로 연 다음 **홈 화면에 추가**하면 아이콘이 생기고, 주소창 없는 전체화면으로 뜬다. 설치한 앱과 구분이 안 된다.

- **아이폰** — Safari로 열고 (크롬 말고 **Safari 여야 한다**) 아래 공유 버튼 → `홈 화면에 추가`
- **안드로이드** — Chrome으로 열고 우측 상단 ⋮ → `홈 화면에 추가` 또는 `앱 설치`

들어가 있는 것: 전체화면 실행, 프리미어리그 사자 홈 화면 아이콘, 세로 고정, 노치·하단 제스처바 여백 처리.

아이콘은 ESPN이 제공하는 리그 로고에서 워드마크를 빼고 사자만 크롭해 만든다(`make_icons.py`). 프리미어리그 로고는 리그의 상표이므로 개인 내기 앱 식별용으로만 쓴다.

인터넷 없이 여는 오프라인 모드는 넣지 않았다. 어차피 매번 최신 순위를 받아와야 하는 앱이라 의미가 없다.

> 공개 저장소의 Pages는 **링크를 아는 누구나 접근할 수 있는 공개 인터넷**이다. 개인적인 내용이나 회사 관련 정보는 절대 넣지 말 것.

## 화면

| 탭 | 내용 |
|---|---|
| 리더보드 | 참가자 순위. **현재 순위 / 마감 예측** 토글. 이름 아래 다섯 개의 팀 로고가 각각 몇 점을 벌었는지 보여준다 — 만점(6점)은 금색 링, 놓친 팀은 흑백. 카드를 누르면 팀별 내역이 펼쳐진다 |
| EPL 순위 | 20팀 순위표. **현재 순위 / 마감 예측** 토글. 예측 쪽은 현재 대비 순위 변동, 5위 안 진입 확률, 예상 최종 승점을 보여준다. 팀을 누르면 선수단과 일정 |
| 일정 | 다가올 경기와 최근 결과 |
| 예측 | 참가자별 1위 확률, 팀별 5위 진입 확률 |

### 기대 점수와 우승 확률이 다를 때

예측 탭에서 **기대 점수는 낮은데 우승 확률은 더 높은** 사람이 나올 수 있다. 버그가 아니다.

- **기대 점수** = 전체 시뮬레이션의 평균. "보통 몇 점 나오나"
- **우승 확률** = 그중 실제로 1등한 비율. "몇 번 이기나"

확률 낮은 시나리오에서 크게 터지는 픽은 평균을 끌어올리지만 매번 이기지는 못한다. 반대로 흔한 시나리오에 맞춘 픽은 평균이 조금 낮아도 이기는 횟수가 많다. 내기는 평균이 아니라 그 판의 최고점으로 가리므로 **우승 확률 쪽이 실제 승부에 가깝다.**

리더보드의 `마감 예측` 점수는 또 다르다. 평균이 아니라 **모든 팀이 자기 평균 순위에 앉은 대표 시나리오 한 판**을 채점한 값이다. 현실에서 그런 판은 거의 안 나오므로 셋이 어긋나는 게 정상이다.

## 검증

```bash
node verify.js          # 실제 ESPN API를 호출해 82개 항목 검사
node verify.js --fast   # 시뮬레이션을 1000회로 줄여 빠르게
```

`verify.js` 는 `index.html` 안의 스크립트를 **그대로 꺼내서** 돌린다. 로직을 복사해 두지 않으므로 앱과 검증이 어긋날 수 없다.

검사 항목: 채점 규칙 32개 조합 대조표, 총점·만점 정합성, 동점 처리, 확률 모델과 룩업표 파리티, ESPN 응답 수신, 순위표 자체 교차검증(승점 = 승×3+무 등), Elo 구성과 제로섬 보존, 시뮬레이션 확률 합, 엔드포인트별 응답 구조 차이, 탭 진입 회귀, 홈 화면 앱 구성, 외부 의존성 검사.

## 데이터

ESPN 공개 API. API 키가 필요 없고 `Access-Control-Allow-Origin: *` 이라 브라우저에서 직접 부를 수 있다.

| 쓰임 | 엔드포인트 |
|------|-----------|
| 현재 순위 | `/apis/v2/sports/soccer/eng.1/standings` |
| 전시즌 최종 | 같은 주소 + `?season=2025` |
| 전체 일정 | `/apis/site/v2/.../scoreboard?dates=YYYYMMDD-YYYYMMDD` |
| 선수단 | `/apis/site/v2/.../teams/{id}/roster` |
| 팀 로고 | `a.espncdn.com/combiner/i?img=/i/teamlogos/soccer/500/{id}.png&h=64&w=64` |

외부 라이브러리는 하나도 쓰지 않는다. 파일 하나가 전부다.
